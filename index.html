NASA Mars to Table Challenge — Technical Overview

Resilience-first observability
for closed-loop life support.

A containerized ingest pipeline built to treat sensor noise, drift, and dropout as expected conditions — not failures — across both UAV flight systems and fermentation-based food production.

01 — The Problem

Efficiency is a trap. Design for the survivable range.

Martian environments don't produce clean telemetry. Sensors drop readings, conditions drift outside modeled ranges, and the system still has to hold. This project's premise: build for the widest tolerance that keeps working, not the tightest number that looks good in a demo.

02 — Architecture

A single ingest path, fully containerized.

FastAPI ingest surface — every reading enters through one endpoint
PostgreSQL / pgvector structured history + similarity search across prior runs
MinIO object storage for raw sensor payloads
Docker Compose reproducible deployment, laptop to lander

03 — Signal Bridge

Two domains, one instrument.

Flight telemetry and fermentation telemetry ask the same question: is this system still inside its survivable range? The mapping below is the core technical claim of this project.

UAV Parameter Fermentation Parameter
Fuel cell stack temperature Vessel temperature
IMU drift / attitude noise pH drift / probe noise
Battery reserve vs. cell redundancy Pitch rate vs. microbial redundancy
Telemetry packet loss Sensor dropout in tank
Gust / control-surface correction CO₂ spike / valve correction
